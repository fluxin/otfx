# Thunderstorm whole-text illumination

2026-09-27, follow-up to `c5722a3a`.

Previously only lightning particles flashed. Text directly beneath a bolt became
orange after the bolt faded, but the rest of the text stayed at storm brightness.
The Python reference also illuminates all text during a strike.

`thunderstorm_build` now prepares a bright color per input particle using the
same 1.7 brightness factor as the reference. During the existing 42-tick bolt
flash, all text follows seven samples: storm → bright → storm, held six ticks
each. Only sample boundaries visit the text; held ticks retain the existing
early return. A new flash replaces prior afterglow. After the bolt's fade,
only its directly struck cells start the existing orange cooling sequence.

This intentionally retains native strike timing rather than importing Python's
randomized easing or lengthening the animation. It adds no RNG calls, scheduler,
renderer path, or playback allocation. The new color array costs four bytes per
input particle. Existing background colors and `always` input-color policy remain
intact. Rain/sparks can still cover text through the normal cell layers.

## Validation

- `odin check src`, optimized release build, and **88/88 tests pass**.
  The two existing assertion-test arena-leak warnings remain.
- New regression verifies a bolt covering B also illuminates unstruck A/C,
  returns all text to storm colors, then applies afterglow only to B. It covers
  ignore/dynamic/always policies, background retention, and replacement of an
  earlier glow. Renderer winners are checked after composition.
- **24 full-animation captures**: Omarchy logo and colored Unicode input,
  seeds 1/3/42, ignore/always/dynamic/no-color. Every frame retains the same glyphs
  and positions, frame counts agree, and final cells are identical. No-color and
  always streams retain identical reconstructed cells throughout. Color changes
  in the animated policies are intentional.
- Thunderstorm's GIF was regenerated by the native Odin `tools/docs` tool:
  **305 GIF frames from 911 logical frames**, unchanged sampling and duration.
  It decodes successfully. Before/after images at the first flash peak confirm
  the whole-text illumination; the existing Odin glyph renderer is unchanged.

## Cost

Frozen before/after release binaries use `-o:speed -microarch:native
-disable-assert`, without `-debug`. Same dense input/default canvas 190×46,
terminal 200×50, seed 1, CPU 2, stdout `/dev/null`. Whole CLI, three batched
samples of at least 0.5 seconds, before then after. `--virtual-clock` and
`--storm-time 12` fix the logical workload; these are not wall-clock storm
throughput or paced CPU-duty claims.

| Metric | Before | Whole-text flash |
|---|---:|---:|
| Mean wall | 5.9 ms | 8.2 ms |
| Mean child CPU | 5.8 ms | 8.1 ms |
| Maximum RSS | 11420 KiB | 11424 KiB |
| Logical frames | 1007 | 1007 |

The additional global illumination costs **2.3 ms per complete logical run**
(about 39% of this small unpaced workload). No speedup is claimed. The 35 finite
effects are unchanged and were not rebenchmarked; the published release chart
remains a measurement of the preceding frozen binary.

Artifacts: `/tmp/otfx-thunderstorm-flash-20260927/` contains the old source/GIF,
frozen release binary and wrapper paths, benchmark/test logs, capture validator
and results, regenerated preview log, and before/after flash images. The prior
preview's four strikes correctly highlighted 11, 6, 2, and 5 struck cells;
this fix supplies the missing whole-text flash rather than changing that lookup.
